# 구현 상세

## 요청 처리

1. 모델이 허용 목록에 있는지 확인합니다.
2. 응답 스키마의 키 개수와 타입 표현을 검증합니다.
3. 입력을 정제하고 최대 길이를 적용합니다.
4. 역할 지시문과 응답 스키마로 시스템 메시지를 만듭니다.
5. 모델을 호출하고 JSON 객체인지 확인합니다.
6. 필수 키와 값 타입을 검증합니다.
7. 성공 또는 실패 결과를 감사 로그에 남깁니다.

## 실패 처리

JSON 파싱과 스키마 불일치는 재시도할 수 있지만, 허용되지 않은 모델·잘못된 요청·빈 입력은 즉시 거절합니다. 모든 예외를 재시도하면 잘못된 요청이 모델 부하로 이어질 수 있기 때문입니다.

## 로그 정책

원본 VOC에는 개인정보와 고객 문의 내용이 포함될 수 있습니다. 공개 예제는 원문을 저장하지 않고 SHA-256 해시와 문자 수만 기록합니다. 같은 요청의 반복 여부는 확인할 수 있지만 로그만으로 원문을 복원할 수 없습니다.

## 확장 지점

`ModelGateway` 인터페이스를 기준으로 Ollama 외 다른 모델 실행기를 연결할 수 있습니다. 업무 로직은 모델 SDK에 의존하지 않아 테스트에서는 가짜 응답을 사용합니다.
